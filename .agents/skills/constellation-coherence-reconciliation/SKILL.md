# Simulation constellation coherence reconciliation

## Contract

- **What:** A receiving-repository method that settles exact sibling release
  identities and their declared semantic relations across the constellation
  lock, living orientation carriers, and validators.
- **When:** A Program, Governance, Implementation, or Comparison release is
  accepted; a living carrier claims current constellation state; or copied
  closure and schema meaning may have diverged.
- **Boundaries:** Each sibling retains authority for its released behavior and
  artifacts. The signed Simulation release and retained selected-future bundle
  remain immutable. Release subjects, later observation carriers, evidence
  modes, and publication identities remain distinct. A semantic change to the
  selected future requires a successor identity.
- **Result:** Exact source coordinates, declared equality modes, horizon state,
  and next receiver agree across living carriers. Unresolved differences route
  to the source that can settle them.

## Fit and attention

- **Useful when:** The repository admits a new accepted sibling coordinate or
  changes a cross-repository summary while retaining the current signed
  selected-future release.
- **Poor fit when:** One local source file changes while every sibling
  coordinate, copied semantic relation, living handoff, and release summary
  remains settled.
- **Smallest useful dose:** Check the exact tag subject, commit, tree, archive,
  declared closure relation, current horizon item, and receiving handoff for
  each decision-changing role.
- **Interactions:** Use `source-authority-mapping` to locate the defining source
  and receiver. Use repository re-entry to distinguish accepted release state
  from living integration state.
- **Rest or release when:** Exact-source validation passes, living carriers
  agree, the signed bundle remains unchanged, and any waiting route has a named
  entry signal.

## Rules

### Rule: Coordinate freshness and semantic freshness settle together

A role becomes current when its accepted source coordinate and every
decision-changing semantic relation agree. Tag, commit, tree, and archive
identify source; canonical closure, schema binding, and receipt fields describe
the receiving relation.

### Rule: Living carriers advance while the signed release remains immutable

`constellation.lock.json`, `COORDINATION-HORIZON.json`, `first-receipt.json`,
and README orientation can reflect a later accepted sibling release while the
signed Simulation tag and retained bundle remain unchanged. State that
distinction directly and verify the immutable bytes.

### Rule: Shared closure keeps repository identities distinct

Simulation and Comparison can carry the same canonical closure digest while
their tags, commits, trees, archives, evidence roles, and release authorities
remain distinct.

### Rule: Release subjects remain distinct from later carriers

Record annotated tag object, peeled commit, Git tree, and reproducible archive
as the release subject. Record a later receipt, orientation correction, or
Pages carrier through its own relation. A carrier can observe or publish a
release while the accepted Git objects remain its subject.

### Rule: Projection drift and semantic drift take different routes

A stale living summary can be corrected in place. A changed assumption,
fixture, modeled authority, database oracle, generated artifact, or closure
meaning forms a successor future-reality identity and release route.

### Rule: Horizon state advances on evidence

Complete a receiving item only after its named coordinate and relation are
accepted. Move an extension out of `waiting` only after its material benefit,
contract, evidence mode, qualification cost, and comparator effect are named.

### Rule: The source owner resolves divergence

When a coordinate or copied semantic relation differs from its accepted owner,
update the living projection from that source or return the mismatch to that
owner. A replacement coordinate comes from its accepted source.

## Operating sequence

1. **Map roles and receivers:** Name each sibling source, living Simulation
   field or artifact, and decision-changing relation.
2. **Capture release subjects:** Resolve annotated tag object, peeled commit,
   tree, reproducible archive digest, and distinct semantic release name.
3. **Inventory living meaning:** Locate closure digests, schema bindings,
   coordinate status, current horizon item, handoff, and README summary.
4. **Compare by declared rule:** Apply byte equality, canonical JSON equality,
   schema validation, or an explicitly derived relation against exact sources.
5. **Classify the change:** Distinguish a living projection correction from a
   selected-future semantic change.
6. **Update one coherent state:** Change lock, horizon, receipt, summary, and
   validators together when they share the same accepted event.
7. **Verify preservation:** Run the aggregate validator and release verifier;
   confirm regenerated closure equality and unchanged retained release bytes.
8. **Publish re-entry:** Name the current receiver, any waiting entry signal,
   and the event that reopens reconciliation.
